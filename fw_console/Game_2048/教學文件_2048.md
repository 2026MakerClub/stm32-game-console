## 1. 專案概覽

### 遊戲規則
2048 是一款在 4×4 格子上進行的數字拼圖遊戲：
- 每次滑動（上/下/左/右），所有磁磚朝該方向移動到底。
- **相同數字的兩塊磁磚相撞時合併**，數值加倍，同時加到得分。
- 每次成功移動後，隨機出現一塊新磁磚（值為 2 或 4）。
- **目標**：拼出一塊值為 **2048** 的磁磚。
- 若棋盤填滿且沒有任何相鄰同值磁磚，遊戲結束（Game Over）。

### 用到的 STM32F407 功能
| 功能 | 用途 |
|------|------|
| LCD (FSMC) | 顯示格板、數字、得分 |
| Touch Screen (SPI) | 偵測滑動手勢、按下「New Game」 |
| SysTick (`msTick`) | 計時（防抖、隨機種子） |

## 2. 硬體與螢幕佈局

### LCD 解析度
ILI9341，橫式（Landscape），**320 × 240 像素**。
Font20 = 每個字元 **14 px 寬 × 20 px 高**。

### 畫面分區

```
X=0                        X=319
Y=0  ┌────────────────────────────────────┐
     │ Score: 12345    Best: 56789  [New] │  ← 頂部資訊列 (y=0..39)
Y=39 ├────────────────────────────────────┤
     │                                    │
     │         4 × 4 格板                 │  ← 格板區 (y=39..239)
     │      (59,39)到(260,240)             │
     │                                    │
Y=239└────────────────────────────────────┘
```

### 格板座標計算
```
GRID_X  = 59      格板左上角 x 座標
GRID_Y  = 39      格板左上角 y 座標
CELL_SIZE = 44    每格邊長（像素）
CELL_GAP  = 5     格子間距（像素）
GRID_SIDE = 4×44 + 5×5 = 201 px（含外框）

格子 (row, col) 的像素座標：
  x = GRID_X + CELL_GAP + col × (CELL_SIZE + CELL_GAP)
  y = GRID_Y + CELL_GAP + row × (CELL_SIZE + CELL_GAP)
```

## 3. 程式架構與執行流程

### 整體執行流程

```
main()
 │
 ├─ stm32f4_Hardware_Init()  ← 時脈、GPIO、SysTick 等初始化
 ├─ LCD_Init()               ← ILI9341 初始化
 ├─ LCD_DisplayOn()
 ├─ LCD_SetFont(&Font20)
 │
 ├─ Game_NewRound()          ← 重設棋盤，放兩塊初始磁磚，繪製全畫面
 │
 └─ while(1)  ← 主迴圈
      │
      ├─ TS_GetState(&ts)    ← 讀取觸控狀態
      │
      ├─ 若剛按下（was_touching=0 → TouchDetected=1）
      │   ├─ 記錄起點 (g_sx, g_sy)
      │   └─ 若在 New Game 按鈕範圍 → Game_NewRound()
      │
      ├─ 若正在觸碰 → 持續更新終點 (g_ex, g_ey)
      │
      └─ 若剛鬆開（TouchDetected=0 → was_touching=1）
          ├─ 計算 dx = g_ex - g_sx, dy = g_ey - g_sy
          └─ Handle_Swipe(dx, dy)
               ├─ 判斷方向（絕對值較大的軸決定方向）
               ├─ 呼叫 Move_Left/Right/Up/Down()
               ├─ 若有移動 → Add_RandomTile()
               ├─ Draw_Board(), Draw_Score()
               ├─ Check_Win() → 顯示 "You Win!"
               └─ Check_GameOver() → 顯示 "Game Over"
```

## 5. 函式詳解

### `main()`
```
目的：程式入口，完成初始化後進入無窮事件迴圈。
輸入：無
輸出：無（永不返回）
```

**關鍵邏輯：觸控狀態機**
```c
if (ts.TouchDetected) {
    if (!g_was_touching) {
        // 「剛按下」事件 —— 只在按下瞬間觸發一次
        g_sx = ts.x;  g_sy = ts.y;
    }
    g_ex = ts.x;  g_ey = ts.y;   // 持續追蹤手指位置
} else {
    if (g_was_touching) {
        // 「剛鬆開」事件 —— 此時計算滑動向量
        Handle_Swipe(g_ex-g_sx, g_ey-g_sy);
    }
}
```
> **為什麼要分「剛按下」和「剛鬆開」？**
> `TS_GetState()` 每次呼叫都回傳目前的觸控點。如果沒有邊緣偵測，只要手指放在上面就會重複觸發。用 `g_was_touching` 比較前後狀態，就只在「狀態改變的那一刻」執行動作，和電路裡的邊緣觸發概念相同。

### `Game_NewRound()`
```
目的：將棋盤歸零、重置得分與狀態旗標、放兩塊初始磁磚、重繪全畫面。
呼叫時機：程式啟動時、按下 New Game 按鈕時。
```

```c
Draw_Board();       // 重畫所有磁磚
Draw_Score();
Draw_NewGameBtn(0);
```

### `Add_RandomTile()`
```
目的：在棋盤上的隨機空格放一塊新磁磚（90% 機率是 2，10% 是 4）。
呼叫時機：每次成功移動後。
```

**兩步驟算法：**

*步驟 1：收集所有空格位置*
```c
uint8_t pos[16][2];  // 最多 16 個空格
uint8_t count = 0;
for (r=0; r<4; r++) for (c=0; c<4; c++)
    if (g_board[r][c]==0) { pos[count][0]=r; pos[count][1]=c; count++; }
```

*步驟 2：從中隨機選一個，放 2 或 4*
```c
uint8_t idx = Rand_LCG() % count;
g_board[pos[idx][0]][pos[idx][1]] = (Rand_LCG()%10 < 9) ? 2 : 4;
```

> 為什麼用兩步驟而不是直接「隨機嘗試直到找到空格」？
> 兩步驟保證 O(N²) 時間複雜度。後者在棋盤快滿時可能需要嘗試很多次，最壞情況不可預測。

---

### `Move_Left()` / `Move_Right()` / `Move_Up()` / `Move_Down()`
```
目的：朝指定方向移動所有磁磚，合併相同值的相鄰磁磚。
回傳：1 = 棋盤有改變（至少一格移動或合併）；0 = 無任何變化。
```

**以 `Move_Left()` 為例的三步算法（見第 6 節詳解）：**

```c
for (每一列 r) {
    uint16_t tmp[4] = {0};

    // 步驟 1：壓縮（把非零值靠左推）
    k=0; for(c=0;c<4;c++) if(g_board[r][c]) tmp[k++]=g_board[r][c];

    // 步驟 2：合併（相鄰且相等的兩格合為左格×2）
    for(c=0;c<3;c++) if(tmp[c] && tmp[c]==tmp[c+1]) {
        tmp[c]<<=1;          // 等同於 tmp[c] *= 2
        g_score += tmp[c];
        tmp[c+1] = 0;
    }

    // 步驟 3：再次壓縮
    uint16_t result[4]={0}; k=0;
    for(c=0;c<4;c++) if(tmp[c]) result[k++]=tmp[c];

    // 步驟 4：寫回並偵測是否有變
    for(c=0;c<4;c++) { if(g_board[r][c]!=result[c]) moved=1; g_board[r][c]=result[c]; }
}
```

**`Move_Right()` 的差異**：逆向遍歷（right→left），壓縮時靠右排列。
**`Move_Up()` / `Move_Down()`**：以「列（column）」而非「行（row）」為內迴圈單位，其餘算法相同。

### `Check_GameOver()`
```
目的：判斷是否無法再進行任何移動。
回傳：1 = 結束；0 = 還可以移動。
```
結束條件（需全部成立）：
1. 棋盤上沒有空格（否則一定可以移動）
2. 沒有任何水平相鄰同值格對
3. 沒有任何垂直相鄰同值格對

```c
for (r=0; r<4; r++) for (c=0; c<4; c++) {
    if (g_board[r][c] == 0)                          return 0; // 有空格
    if (c+1<4 && g_board[r][c]==g_board[r][c+1])    return 0; // 可水平合併
    if (r+1<4 && g_board[r][c]==g_board[r+1][c])    return 0; // 可垂直合併
}
return 1;  // 以上皆無 → 結束
```

```c
for (r=0;r<4;r++) for(c=0;c<4;c++) if(g_board[r][c]>=2048) return 1;
```

### `Handle_Swipe(dx, dy)`
```
目的：根據滑動向量（dx, dy）決定移動方向並執行。
```
**方向判斷邏輯：**
```
計算絕對值 adx=|dx|, ady=|dy|

若 adx, ady 都 < SWIPE_MIN → 太短，忽略

若 adx >= ady（水平方向為主）：
    dx > 0 → 向右滑 → Move_Right()
    dx < 0 → 向左滑 → Move_Left()

若 ady > adx（垂直方向為主）：
    dy > 0 → 向下滑 → Move_Down()
    dy < 0 → 向上滑 → Move_Up()
```

### `Log2Idx(val)`
```
目的：計算整數的 log₂ 作為顏色表索引。
演算法：將 val 不斷右移（÷2），計算移了幾次才變成 1。
```
```c
// 範例：val=8 → 8>>1=4 >> 1=2 >> 1=1 → idx=3
uint8_t idx = 0;
while (val > 1) { val >>= 1; idx++; }
return idx;
```

---

### `Rand_LCG()`
```
目的：偽隨機數生成器，使用線性同餘法（LCG）。
```
```c
// 先混入當前毫秒計時器和得分，讓每局的序列不同
g_rand_state ^= (msTick * 2654435761UL) ^ ((uint32_t)g_score << 7);
// 標準 LCG 遞推公式（Numerical Recipes 常用係數）
g_rand_state  = g_rand_state * 1664525UL + 1013904223UL;
return g_rand_state;
```
> **為什麼不用 C 標準庫的 `rand()`？**
> 嵌入式環境下，`rand()` 可能不夠快，且需要設定種子才有意義。自製 LCG 輕量、可控，混入 `msTick` 確保每次遊戲的亂數序列不同。

## 6. 演算法深入解說

### 2048 移動合併算法圖解（以向左移動一列為例）

假設這一列是：`[ 2, 0, 2, 4 ]`

**步驟 1：壓縮（compact）**
移除零，把非零值靠左：
```
[ 2, 0, 2, 4 ]
      ↓
[ 2, 2, 4, 0 ]
```

**步驟 2：合併（merge）**
左→右掃描，兩個相鄰且相等的合為左格（翻倍）：
```
[ 2, 2, 4, 0 ]
  ↑  ↑
  相等 → 合併
      ↓
[ 4, 0, 4, 0 ]   得分 += 4
```

**步驟 3：再次壓縮**
```
[ 4, 0, 4, 0 ]
      ↓
[ 4, 4, 0, 0 ]
```

**最終結果：`[ 4, 4, 0, 0 ]`**，棋盤改變，`moved = 1`。

> **為什麼要合併後再次壓縮？**
> 步驟 2 的合併會在原位留下一個 0（被合併的右格清零），若不再壓縮，零洞會留在中間。

> **為什麼合併只掃一次（不迴圈）？**
> 2048 規則：每次移動中，一塊磁磚只能參與一次合併。例如 `[2,2,2,2]` 向左後應為 `[4,4,0,0]`，而非 `[8,0,0,0]`。只掃一次就自然滿足此規則。

### Move_Up / Move_Down 的實作思路

把「按列（column）提取」替換「按行（row）提取」，壓縮方向取決於 Up（索引 0 在上）或 Down（索引 N-1 在上）。程式碼使用反向迴圈 `for(r=BOARD_N; r-->0; )` 來做「靠下壓縮」，等同於 Move_Right 的鏡像。

## 7. 觸控輸入與手勢偵測

### TS_GetState 的工作方式

`TS_GetState(&ts)` 透過 SPI 讀取觸控 IC（XPT2046），回傳：
- `ts.TouchDetected` ：1 = 有觸碰，0 = 無
- `ts.x, ts.y`       ：目前觸碰點的像素座標（已做校正）

### 邊緣偵測（Edge Detection）

```
迴圈 N       迴圈 N+1      事件
──────────────────────────────────
touch=0   → touch=1    →「剛按下」→ 記錄起點，檢查按鈕
touch=1   → touch=1    → 持續觸碰 → 更新終點座標
touch=1   → touch=0    →「剛鬆開」→ 計算 dx/dy，判斷方向
touch=0   → touch=0    → 無動作
```

```c
// 在 main loop 中實作邊緣偵測
if (ts.TouchDetected) {
    if (!g_was_touching) { /* 剛按下 */ g_sx=ts.x; g_sy=ts.y; }
    g_ex=ts.x; g_ey=ts.y;
} else {
    if (g_was_touching)  { /* 剛鬆開 */ Handle_Swipe(g_ex-g_sx, g_ey-g_sy); }
}
g_was_touching = ts.TouchDetected;
```

### SWIPE_MIN 閾值的意義

`SWIPE_MIN = 28 px`（約 2 個字元寬）。目的：

| 移動距離 | 判斷 |
|---------|------|
| < 28 px | 視為點擊（tap），不移動棋盤 |
| ≥ 28 px | 視為滑動，按較大分量決定方向 |

## 8. 如何建立 Keil 專案

### 步驟

1. 在 Keil 中複製（另存新專案）現有課程專案（例如 STOP_STANDBY_9）。
2. 在「Project」→「Manage Project Items」中：
   - 從 build target 移除 `main_PWR.c`（或任何其他含 `main()` 的檔案）。
   - 加入 `main_2048.c`。
3. 確認其餘課程檔案（`HardwareSystem_Ini.c`, GLCD driver, `touch_module.c`, `user_defined.c` 等）都在 build 中。
4. **Rebuild All**（Project → Rebuild All Target Files）。
5. 確認無 error，下載到板子（Flash → Download）。

| 錯誤訊息 | 原因 | 解法 |
|---------|------|------|
| `L6200E: Symbol 'main' multiply defined` | 專案中有兩個 main() | 確認只有 main_2048.c 在 build 中 |
| `undefined identifier 'Font20'` | 字型檔未加入 | 確認 `GLCD/Fonts/font20.c` 在 build 中 |

## 9. 擴展方向

### 增加動畫效果
在 `Draw_Tile()` 後加入短暫的顏色閃爍，讓合併的磁磚「發光」：
```c
// 合併發生後（在 Move_Left 裡），設旗標 merged[r][c]=1
// Draw_Tile 根據旗標短暫改用亮色，然後還原
```

### 儲存最高分到 Flash
使用課程的 `User_FLASH_SectorErase()` / `User_FLASH_beforeWRITE()` 把 `g_best` 存入 Flash，重開機後讀回。

### 加入過場動畫
每次移動前，先用動畫展示磁磚滑動，再到達最終位置，讓遊戲感覺更流暢。

### 多難度模式
在遊戲開始前加一個難度選擇頁面：
- 簡單：在 3×3 格板上玩（`BOARD_N=3`）
- 普通：4×4（預設）
- 困難：加入「3」磁磚（不只有 2 的冪次）
